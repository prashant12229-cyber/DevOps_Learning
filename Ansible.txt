Ansible

Difference in Terraform and Ansible 
Terraform is use to create infrastructure on different Cloud providers as a code. in AWS we have cloud formation, in Azure we have templates. 
We can't use cloud formation on all cloud provider. we can say terraform is cloud independent IAAC language

Ansible is an open-source automation tool mainly used for:
Configuration management
Server provisioning (creating user, changing passwords, directory setup etc, system updates)
Application deployment
Infrastructure as Code (IaC)

Ansible(IAC) have the module using which we can create infrastructure on cloud as well. 
but we use ansible for configuration management where terraform is for infrastructure creation.configuring infra mean Vm os, etc etc.


a system admin or release engineer has a lot of daily repetitive tasks like creating the VMs, configuring them, migration of code, and application deployment 
which is a little hectic task So a smarter way to achieve this is by scripting it. This means the script will take care of the building of the entire infra.

Ansible is Agentless, means it is not require to install ansible on client machine.

---------------------------------------- Lecture 3 Ansible configuration.

Note : It is required to have installed python 2.4 or above on Ansible Controller server. because Ansible is written in python language only
		Ansible communicate with other machine using SSH port 22, due to which it become agentless


Note : In Ansible system, We have one Controller machine and any other machine is known as worker node. 
		1. Controller machine must be able to communicate with all the worker nodes
		2. We need to install ansible on controller node only. 
		3. Ansible push any task from Controller to worker node using ssh port 22 and
		4. it is required to have ssh passwordless 	connection between controller and worker node. 
		


Command to check rpm package for ssh : rpm -qa | grep openssh
Command to remove rpm package : rpm -e package_name
	
	
command to install ansible package : yum install ansible* -y 


Note :  1. ansible have a inventory file that consist of list of worker node host, where ansible can perform any task on those host. 
		2. We can define the userid and password of worker node in inventory file as well, using which ansible will login into target machine.
		3. if we did'nt pass than asnible will prompt for password.
		
		ansible --version			// this will show ansible, python version along with the ansible configuration file. : 
									/etc/ansible/ansible.cfg
										 
										
		configuration file. : /etc/ansible/ansible.cfg				//ansible.cfg file will have path of inventory file.
										
		location of inventory file  : /etc/ansible/hosts
		
		ansible all --list-hosts			// list all the host in inventory file.
		
Entries in inventory file. : we can create the different groups of hosts using [] brackets
			example :	[web-server]
						192.178.34.51
						10.20.30.10
						[app-server]
						172.34.56.21
						172.34.87.21
now we can list out only specific group of servers : ansible web-server	--list-hosts
												   : ansible app-server --list-hosts
					to list multiple hosts groups  : ansible web-server:app-server --list-hosts	 
				

parent and children group creation : 
	Example: 
	
	[production:children]
	web-server

	when we list production group than it will list list of "web-server" and "app-server" groups server list.

-------------------------------------------------------Lecture 5 Ansible Module

An Ansible module is a small, reusable program or script that acts as a unit of work within the Ansible automation framework
We have different different module for different kind of task. like copy module package installing module etc

 
Command to perform task on specific machines :
	ansible target -m command   -a "uptime"
	ansible [group_name] -m command -a "uptime"
	ansible web-servers -m command -a "uptime"
	
	
Note : If we are running a task on target node using root user than ansible will perform that using same root user. 
		command module we can use to run any command on worker node. but only one command we can run at a time.
	

Note : Whenever ansible take the login in worker node it askfor key verification permission, so if we have 100 of node as worker than we need to verify 100 times.
		to avaid such condition, we can remove the host key verification.
		
		ansible web-servers -m command -a "uptime" -k				//-k will prompt for password.
		ansible --version
		vi /etc/ansible/ansible.cfg
		search for host_key_checking = False and uncomment this line

Note : When we run the command on worker node it will deny the login, because the machine will treat the attempt as ssh passwordless login attempt, and we have not did it yet.
		so we should have the password for target machine if we have not setup password less connection.

lineinfine module : used to ensure a specific line is present or absent in a file, or to replace an existing line that matches a regular expression
				   using this we can change or replace the text in file available in target system.
				   
commands :
ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL"'			//command will add the given line in the target file at the bottom

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL" state=absent'			//command will remove the given line from the target file 

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL" insertafter=BOF'			//command will add the given line in the target file at begining of the file.

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL" insertafter=BOF state=absent'			//command will remove the given line from the target system from the begining of the file.

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL" insertafter=EOF'			//command will add the given line in the target file at ending of the file.

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL" insertafter="^root"'			//command will add the given line in the target file after the line having word root of the file.

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL" insertbefore="^root"'			//command will add the given line in the target file before the line having word root of the file.

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL" insertbefore="^root" state=absent'			//command will add the given line in the target file before the line having word root of the file.

ansible all -m lineinfine -a 'path=/etc/sudoers line="ALL=(ALL) ALL regex="^root"'		//to replace

Sample LAB : We are going to run a website which we deploy on target systems, website will be host on httpd.

Download a sample website, and place it in ansible controller 


myplaybook.yml 
		
		- hosts: all
			tasks:
				- yum: 
				    name: httpd
				    state: latest
				  
				- copy: 
					src: /sourcecode/
					dest: /var/www/html/
				
				- lineinfile:
					path: /etc/httpd/conf/httpd.conf
					regex: '^Listen'
					insertafter: '#Listen'
					line: 'Listen 8080'
					
				- firewalld:
					port: 8080/tcp
					permanent: true
					state: enabled
					immediate: true
				- service:
					name: httpd
					state: started
					
Now the above code will deploy the static website on port 8080, and start the service as well.
