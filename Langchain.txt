Generative AI

What is generative AI ??
GenAI is a type of artificial intelligence that have capability to create new content such as text, images, music or code that never exist.
by learning patterns from existing data, mimicking human creativity.

base of AI is machine learning where we provide large dataset to mathematical algorithms, which extract patterns from the given dataset and than it can predict
new patterns or new content. like predicting new stock price after reading historical data etc.

Phases through which the GenAI has to go 
	
	Artificial Intelligence -> MachineLearning -> Deep Learning -> Generative AI
	
Artificial Intelligence : it referes to machine capabilities of performing task typically need human intelligence.
							like decision making, problem solving, understanding language.	
							
Machine learning : learning from data, no explicit programming, identify patterns, make predictions.
Types of machine learning
		
		Supervised learning: use labeled data to train models, like predicting stock price on the basis of historic data.
		unsupervised learning: finding hidden pattern without labels like grouping customer on the basis of behaviour.
		Reinforcement Learning : involve models learning through trails and errors, where model will learn by interecting with environment and improve itself 
									trough trial and errors.
									
Machine learning is like : Teaching a dog to fetch, throw the ball repeatedly and through repetition and rewards the dog learns.
							after every repetition the machine learns more.
							

Deep Learning: Neural networks to automatically learn features from raw data.
				A Neural Network is a machine-learning model that learns patterns from data and uses those patterns to make predictions or decisions.
	Example:
	Recognizing faces in the crowd or understanding spoken language
	Convolution Neural network (CNN) for image data
	Recurrent Neural Network (RNN) for sequential data like text
	Transformers, A Transformer is a type of neural-network architecture designed especially for working with sequences of data, particularly text.
	
Foundation Model : the model that were trained on huge dataset.



GenAI : AI models that generates new original content that does not exist before, weather it is writing text, drawing image, composing music, or even generating code.
		
How GenAI works
	
	Train -> Learn  -> Output generation -> Feedback loop 
	
	1. Training Data : Training a AI model on large data set of Audio, Video, Text.
	2. Learn :  Neural Network of AI model learns pattern from the data.
	3. Generate : Generate the data on the basis of the data it was learned.
	4. Feedback Loop : Taking the feedback and improve itself.
	
Type of Generative AI models
	
	1. Generative Adversarial Network, or GANs : For Image Generation, it have two neural networks Generator and discriminator
	2. Variational Autoencoders or VAEs : Reconstructing data and Generating a new variation. Encode data into a lower dimentional space(latemt space) capture the feature of the data then decode from this space to create new variation of the original data. 
											Vaes are often used to reconstruct medical images such as filing in missing or damaged parts of MRI.
	3. Transformer models (Chat GPT) : This model calculates that which words are important to each other in a sentence.
		
		Example: 
		"I deposited money in the bank."  : The word bank could mean a financial institution.
		"I sat near the river bank."    : Here bank has a different meaning.

The Transformer looks at surrounding words and determines the relationship:

What are LLM's : llms are trained on large datasets, massive amount of text from book, websites, research papers.
					ability to process, generate and interact with human in natural language.
					
Transformers are the heart of LLMs, Model uses the mechanism self attention
important feature is ability of understanding

LLM before processing the text, it breakdown the text into small pieces called tokens.
these tokens can be entire words, part of the subwords or even a single character.

LLM generates text one word or token at a time, predicting  the next word in sentence.

example: The Sky is "blue"  the prediction will continue until it complete the desired output


Token and Tokenization : A token is a smallest unit of text that model can understand
 
Converting any text or prompt into mulitple tokens, and each token is dictionary (key, value)
example: I love cricket

"I"        → 501

"love"     → 892

"cricket"  → 14562

sentence : [501, 892, 14562] : These integers are the input to the AI

Note : The LLM models process the tokens not sentences. 
		user https://platform.openai.com/tokenizer  to view, how tokenization happens
		
Tokens are processed one by one, the model understand the patterns and relationship between tokens.
each model have limit to process the specific number of tokens also called context window.

Langchain : It is a opensource framework that helps in building LLM based applications.
			it provides modular components and end-to-end tools that help developers build complexAI applications, such as chatbot, Q&A system
			Retrieval-augmented generation(RAG), Autonomous Agents.
			
			It is a library that have lots of functions that orchestrate the complete workflow of LLM powered applications.

in simple words LangChain is a Python framework that helps you build AI powered applications by connecting an LLM with other things like databases, 
APIs, tools, memory, and documents.
it is basically a orchestrator.

it support all the major LLMs
Simplifies developing LLM based applications
integration available for all major tools

While building a GenAI Model, we have lots of task which are integrated to each other like below

	
	Bunch of Doc  ->  Cloud Storage(S3) -> Document loader ->  Page 1 -- Text Splitter -> Embedding vector 1
															   Page 2 -- Text Splitter -> Embedding vector 2
															   Page 3 -- Text Splitter -> Embedding vector 3
															   Page 4 -- Text Splitter -> Embedding vector 4
																		|	
															            |
																		
																    Vector Database -> sementic search  -> LLM (Brain)  -> Output
																	
Langchain provides builtin functions using which we can integrate all of the above steps with eachother.
So tommorrow if we have to replace any of the step like cloud provider instead of AWS we want GCP, than we can do that easily without any hustle.
So basically Langchain is Orchestrating the whole process of LLM Powered Application system.


Benefits of Langchain
1. Concept of chains : A sequence of steps where the output of one step becomes the input of the next step.
2. Model augnostic Development : means LLM model independent, we can change any LLM at any point of time without making big changes, just need to change few code.
3. Complete eco system : it provides multiple functions to perform each task like document loader, text splitter, embedding, databases.
4. memory and state handling : it keeps the state of last chat alive through which it answer the next question on the basis of previous chat.

-----------------------------RAG Based Document Search Application.

Example:

from langchain_openai import OpenAIEmbeddings
from dotenv import load_dotenv
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np 

load_dotenv()

embedding = OpenAIEmbeddings(model='text-embedding-3-large', dimensions=300)

documents = [
"Virat Kohli is an Indian cricketer known for his aggressive batting and leadership.",
"MS Dhoni is a former Indian captain famous for his calm demeanor and finishing skills.",
"Sachin Tendulkar, also known as the 'God of Cricket', holds many batting records.",
"Rohit Sharma is known for his elegant batting and record-breaking double centuries.",
"Jasprit Bumrah is an Indian fast bowler known for his unorthodox action and yorkers."
    
]

query = 'tell me about virat kohli'

doc_embeddings = embedding.embed_documents(documents)
query_embedding = embedding.embed_query(query)

scores = cosine_similarity([query_embedding], doc_embeddings)[0]        #finding nearest vector
index, score= sorted(list(enumerate(scores)), key=lambda x:x[1])[-1]
print(documents[index])                 #This will print the Document matching
print('similarity score is  : ', score)

		'length_input': length_input

-------------------------------------------------Structured Output

When we provide input to LLM and get a output, the output is in unstructured format.
Structured output refers to the practice of having language model return response in a well defined data format rather than free form text
This makes the model output easier to parse and work programmatically.

Use case:
	Data Extraction : when we have to store the data given by LLM in to DB.
			Example : like naukri.com we have to extract candidate Resume and on the basis of resume keywords we have to store it into DB.
			
	API Building : 
	Build Agents: Structured output is very useful to make AI agents
	

Some LLM have capability to generate the structured output and some dont have capability to generate structured output.
	LLM having capability : function available -> with_structured_output
	LLM dont have capability : than we need to generate using "output parser"
	
	
	Data formatting 
		1. Typed Dictionary : it is a way to define in python where you specify what keys and values should exist, it help to ensure that your dictionary follows a specific structure.
								like we have already defined a dictionary of name person which contains "Name of String" Type and "Age if Int" Type, now when another person will use the dictionary 
								of person than he can not define age of String type.	
		
Example: 

from langchain_huggingface import ChatHuggingFace, HuggingFaceEndpoint
from dotenv import load_dotenv
from typing import TypedDict, Annotated, Optional

load_dotenv()

llm=HuggingFaceEndpoint(    

    repo_id="meta-llama/Llama-3.1-8B-Instruct",
    task = 'text-generation'
)
model =  ChatHuggingFace(llm=llm)

class review(TypedDict):
    summary : str
    sentiment : str

structured_model = model.with_structured_output(review)
result = structured_model.invoke(""" The Hardware is Great, But the Software feels bloated. There are too many pre installed apps that I can't remove.
                                     Also, the UI looks outdated compared to other brands. Hoping for the software update to fix this.""")

print(type(result))
print(result['summary'])
print(result['sentiment'])

| Method       | Simple meaning                |
| ------------ | ----------------------------- |

| `.stream()`  | Get output **piece by piece** |
| `.ainvoke()` | Async version of `invoke()`   |
| `.abatch()`  | Async version of `batch()`    |
| `.astream()` | Async version of `stream()`   |


langchain team finds when thier is any repetition in the task, they form its chain.
below are the most using chains.

			self.runnable_list = runnable_list
			
		def invoke(self, input_data):
			
			for runnable  in self.runnable_list:

2. PyPDFLoader : it is used to load content from PDF files and convert each page into a document object.
				 It have limitation, it can not process the scanned PDFs.
				 it works page by page, mean if we have 10 pages in PDF than it will create 10 Document objects.
				 
	[
		Document(page_content = "Text from page 1 ", metadata={"page" : 0, "sources" : "file.pdf"})
		Document(page_content = "Text from page 2 ", metadata={"page" : 2, "sources" : "file.pdf"})
		Document(page_content = "Text from page 3 ", metadata={"page" : 3, "sources" : "file.pdf"})
	]
	
Example: 

from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader('xyz.pdf')

docs = loader.load()

print(docs)
print(len(docs))
print(docs[0].page_content)

3. DirectoryLoader : it let you load multiple documents within a directory.

							load returns list of document where lazy_load return a generator of documents
	
example:

----------------------------------------Text Splitter

Text splitting : it is a process of breaking a large text into small small chunks, so that processing on large data can be fast.
				 And also each LLM have context size, mean the size of text a LLM can receive and process at a time.
				 It Overcomes the LLM model limitations.
				 
				 By text splitting the embedding, sementic search and summarization of any text become better
				 
				 While splitting any text into chunk, it does not cares about the grammer, sementic meaning and even word completion as well.
				 
1. Length Based  (CharacterTextSplitter): Simple and fast.
										 it provides the chunks in list format.
										 


Example:

from langchain_text_splitters import CharacterTextSplitter
from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("xyz.pdf")

docs = loader.load()

splitter = CharacterTextSplitter(

    chunk_size = 100,
    chunk_overlap = 0,				//this parameter are the character overlap between two chunks
    separator=''
)

#result = splitter.split_text(text)
result = splitter.split_documents(docs)

print(result[0].page_content)



Note: Due to chunk_overlap, we can make secure the context meaning of the text due to which chunk1 can easily predict the next chunk.
		
		
2. Text Structured based Splitter (RecursiveCharacterTextSplitting) : It try to make chunks on the basis of 

		\n \n : Represent Paragraph
		\na   : Represent Line
		-	  : Words
		.	  : character
		
	This fucntion tries to secure that chunking should not happen in middle of words.
	if the chunk size is bigger than it will try to secure paragraph than line than word and at last character.
	
Example : RecursiveCharacterTextSplitting.py

from langchain_text_splitters import RecursiveCharacterTextSplitter

text = 'The webpage is about Python Modules. A module is a file containing a set of functions that can be used in an application. To create a module, you save the code in a file with the .py extension. You can use a module by importing it and calling the functions or accessing the variables it contains.'

splitter = RecursiveCharacterTextSplitter(

    chunk_size = 100,
    chunk_overlap = 15,

)

chunks = splitter.split_text(text)

print(len(chunks))
print(chunks)

4. sementic meaning based : Let we have text that is talking about 3 different topics in 3 different paragraph, but if we are going to make thier chuks than
							chunk of topic one it going to merge with chunk of topic two. Due to which the whole meaning is not be clear.
							So this sementic meaning text splitter is going to split the text on the basis of meaning of text.
							
from langchain_text_splitters import SemanticChunker
from langchain_openai.embeddings import OpenAIEmbeddings

from dotenv import load_dotenv

load_dotenv()

text_splitter = SemanticChunker(
	
	OpenAIEmbeddings(), breakpoint_threshold_type = "standard_deviation",
	breakpoint_threshold_amount=1
)	

sample = """  the Whole Text """

docs = text_splitter.create_documents([simple])
print(len(docs))

print(docs)



-----------------------------------------------Vector Store.( UNder Text Splitters on VS)
Vector store is required to store the Vector number of token, it is used to make a semantic search.
In SQL Database we can only make search where keywords matches with required value, but using Vector DB we can make semantic search
in which we fetches the meaning given string.


CRUD Operation can also make on the stored vector.

The embedding model decides the vector dimension.

384 dimensions
768 dimensions
1024 dimensions
1536 dimensions
3072 dimensions

FOr making search in vector store,it have to match query vector with stored vector one by one which is lot of time taking. So we use indexing.

We will create cluster of vectors let we have 10 cluster of 1 lakh vectors, and each cluster have n vectors. we will find the average of all 
the cluster which will be the center of all the cluster vectors. than will find the cosine similarity with center cluster vector. 
and than we will make search in only that cluster with which we have highest cosine similarity. 


Vector Store : Storage and Retrieval, they are only liabrary. ex : FAISS, Chroma

Vector DB : ACID Transaction, Concurrency control (multiple user access at same time.), authentication, Backup and Restoration
			It is full fledged Database system designed to store query vectors.
			Database like feature.
			ex : weaviate, Pinecone, Qdrant, Milvus.

Methods in Vector store in langchain are common for different different vector stores.

from_documents(), from_text()
add_documents(), add_text()
similarity_search(query)

1. Chroma Vector Store : light weight vector database that is friendly with local development and small scale production need as well.

-----------------------------------------------Retrievers

Retrievers is the component of langchain that fetches relevant document  from a datasource in response to user query.
All the retrievers are runnables.

It is not a document  loader, it have some kind intelligence, it is a retriver.

Types of Retrievers ?
Datasource based Retrievers : From what datasource we are fetching the document
	
1. Wikipedia Retrievers : it uses wikipedia API to fetch relevant data matches with query
2. Vector Store Retrievers
3. Archive retrievers 

Mechanism based retrievers  : how the search is made


Example : 

from langchain_community.retrievers import WikipediaRetriever

retriever = WikipediaRetriever(
    top_k_results=2,
    lang="en"
)

query = "India Pakistan relations"

print("Searching Wikipedia...")

docs = retriever.invoke(query)

print(f"Number of documents returned: {len(docs)}")

for i, doc in enumerate(docs):
    print(f"\n------- Document {i + 1} -------")
    print(f"Content:\n{doc.page_content[:1000]}")
    print(f"\nMetadata:\n{doc.metadata}")

------------------------------------- Langchain Tools

Tool  ---->   Tool Calling ----------> Agents

Tool : it is just a python function or API, that is packaged in a way the LLM can understand and call when needed
		
		As we know, LLM can think and can generate but it cant perform the task, so we packaged the LLM with Python functions so that it can perform a task.
		
		After Combining the Tools with LLM it becomes Agent, because now it can think, generate and perform the task as well.
		
			
		Types : 
		Build in tools : Langchain provide some of standard tools to integrate.
		Custom Tools : When We want to integrate LLM with our custom application, we need to build our custom tool

There are three ways to create custom tools
-> @tool anotation
-> Using StructuredTool & Pydantic : special tool where  the input to the tool follows a structured schema, typically defined using pydantic model
-> Using Base tool Class : basetool class is the abstract base class for all tools in langchain, it define the tool structure and interface 
							that any tool must follow. ALl the tools types like @tool or StructuredTool are built on the top of it.




-------------------------------------------------------Tool Calling

Tool binding : Step in which we register the Tool with LLM Model, so that LLM knows what tool are available, it knows what each tool does (description),
				and it know what input format to use(Schema)
				
Note : Not all the LLM have capability to bind the Tools.
		The LLM calls the tool only when it is required, not every time it is going to call the Tool.
