----------------------------------------------------------Lecture 5
How to integrate GitHub Account with Jenkins

	Types of Jenkins Jobs
	1. Manual		: Job will run whenever we hit the build command from jenkins (If we dont select any of Job type while creation of Job)
	2. Trigger build remotely :  Triggering the Jenkins Job from any of the remote system
	3. Build after other project are built : when one of the project build completed or it will run when one of its previous job run completed than its build triggers the Job on jenkins 
	4. build periodically : Running a jenkins job in specific time period or also called cron job
	5. Poll SCM : this type will check the new commit in GitHub in specific period, if Commit find than only it will run the job
	6. Github Hook trigger for GITScm Polling : The Job will run whenever developer commit the code and push it into GitHub
												Means it will run everytime when commit comes from Developer
											
Note : For integrating GitHub and Jenkins we need to carry IP, Port and Token from Jenkins and provide it under GitHub
	
	How to fetch the Jenkins token
	Login to Jenkins console -> Click on UserName at the top-right -> now click on configure -> Add Token -> Generate Token -> Copy the token
	
	
	Login to GitHub account, -> Open the Code Repository -> Click on option Webhooks ->
	Click on add webhook
		
		payload Url: http://jenkins-host:8080/github-webhook/
		Secret: Jenkins Token : Token We just Generate on Jenkins console
	
	Add webhook, and now Jenkins and GitHub Is integrated.
	
Note : It is requiredd to have Github Package on Jenkins servers (yum install git)


1. Creating a manual Job
	Jenkins Dashboard -> Click new Item on Left -> Select free style project and Next
	Under source Code Management Select Git and  provide Git Repository Code Url
	Save.
	
	Manual Job Created
	Open the Job and Click Build Now on Left

Note : It is required to install GIT package on Jenkins server other wise we will get an error while adding the repository code URL in jenkins
		yum install git

2. Change Build Triggers to Build periodically
	
	Open the Jobs configuration and tick the check box of build periodically
	under schedule : *****			(5 times astrick, means every minute and every hour)
	
	This will run every min

3. Change Build Triggers to Poll SCM : The Job will not run, because it checks the new commit in periodic interval but run only when commit found.

	Under Schedule : *****			(5 times astrick, means every minute and every hour)
	
	Now to find a new commit, we can either change the code in github directly, but it is not systematic.
	Change the Code on developer machine and commit the changes from there.
	
4. Change Build Triggers to Github Hook Trigger for GITscm polling: This will run the Job whenever we commit code.
	
	Change the Code, and we can running job immediately

Project : We will integrate the below components
Flow : 

					Developer  ------->    GITHUB  --->   Jenkins    --->    Ansible     --->   Web Server


Note : It is require to have passwordless authentication between all servers

We need 4 Servers for Developer, Jenkins, Ansible and Web Server and one GitHUB Account.

Step 1: Install Jenkins on one of the machine

Step 2: Install and configure Ansible Server
		
		Create an entry for Web-Server in inventory file of ansible : 
		
		inventory file : /etc/ansible/hosts
		
Step 3: Do ready the Web server by installing apache httpd 
		install : yum install httpd
		start services : systemctl start httpd
		enable services : systemctl enable httpd
	
Step 4 : creating a passwordless connection between ansible and web server
		
		 command : ssh-keygen 										//this command will create id_rsa and id_rsa.pub file inside /home/user/.ssh/ directory 
		 enable the root login on web-server 
		 passwd root 												//set the root password
		 vi /etc/ssh/sshd_config	
		 uncomment the line #PermitRootLogin yes
		 set 				 password authentication 
		 ssh-copy-id -i root@web-server								//this command will copy the ssh key into web server at /home/user/.ssh/ directory
		 
Note : After sharing the key between ansible and web-server, the passwordless authentication will start working.
		 
		 
Step 5 : Establish the Passwordless authentication between jenkins and Ansible Server, using the similar step performed in last step.

Step 6: Write a ansible code i.e playbook.yml

		
		- hosts: all
		  tasks: 
			- copy:
				src: /opt/index.html						//this index.html file will come from jenkins server after compilation.
				dest: /var/www/html							//copying  the index.html file in html directory
	
Step 6: Create a project on Developer system and Push it to Github,

		open jenkins dashboard -> open configure  on left hand tabs -> API Token (ADD NEW TOKEN) -> Generate Token (Copy the Token and paste it under

Note : We can install Docker on same machine on which we have jenkins, and run the Dockerfile Code to build image and store it their only.
		Or we can do the same any other server as well, like we install Docker on Ansible machine and we run the command for Build, Tagging and Push using jenkins.
		
		
Note : When we are running a docker file second time for image creation, we can't give the Image name, Tag similar as we have given in first run, for which we need to edit the Dockerfile
		again and again. So we use Variables and the build name will be same as the Job name
		
		docker image build -t $JOB_NAME:Prefix.$BUILD_ID
		docker image tag $JOB_NAME:Prefix.$BUILD_ID   sd2234/$JOB_NAME:Prefix.$BUILD_ID				
		docker image push sd2234/$JOB_NAME:Prefix.$BUILD_ID		
		
		Now we can get the new created image using above command, but ansible playbook still have the old one, so we will use the latest tag everytime
		
		docker image tag $JOB_NAME:v1.$BUILD_ID sd2234/$JOB_NAME:latest
		docker image push sd2234/$JOB_NAME:latest
		
		so while writing the playbook for container creation, we will write command only with image name, will not provide the tag, becasue if we are not going to use 
			tag, than it will only pick the latest one.
				
				example: vi docker.yml
				
				- hosts: docker-hosts
				  tasks: 
					-shell: docker container run -it --name cloudknowledge -p 9000:80  sd2234/cloudknowledge
					
					
Note : unnecessarily we are going to have many images on ansible server, so we will remove the image once the image pushed to registry
		docker image rmi $JOB_NAME:v1.$BUILD_ID sd2234/$JOB_NAME:v1.$BUILD_ID sd2234/$JOB_NAME:latest
		
Note: Now when Docker host will get second time run container command, it will for image in its local first, and it will find the image with latest tag in local itself,
		than it will not reach to Docker HUB. so we need to write in playbook something more as below
		
		Example: vi docker.yml
		
		- hosts: docker-hosts
		    tasks: 
			 - name: stop container
			   shell: docker container stop cloudknowledge
			 - name: remove container
			   shell: docker container rm cloudknowledge
			 - name: remove image
			   shell: docker image rmi sd2234/cloudknowledge
			 - name: create new container
			    shell: docker container run -itd --name cloudknowledge-container -p 9000:80 sd2234/cloudknowledge
