-----------------Volumes : Elastic Block Storage

EBS (Elastic Block Storage) : Storage Service provided by AWS, using which we can provision the virtual hard disk volume and attach directly to EC2 Instances.

EBS volumes are designed for persistent storage, meaning the data remains even if the EC2 instance is stopped or terminated.

Type:     GP2,GP3,IO1, IO2, SC1, ST1, Magnetic Disk
Type of EBS (Having More IOPS is having more faster Disk)
GP2: Min 1GB, Max 16TB, IOPS 16000, Throughput 250MB
IO1: min 4GB, max 16TB, IOPS 64000, Throughput 1000MB (4 time faster than Gp2)

AWS S3 and EBS are both storage services, but they serve different purposes. S3 is object storage for storing and retrieving large amounts of unstructured data, while EBS is block storage that provides persistent volumes attached to EC2 instances.

EBS is like a virtual Hard disk, Directly attached to Ec2 for low latency. it is accessed like a file system.(Accessed on Transport layer 4)
S3 accessed via API like HTTP and REST not like a file system. (accessed on Transport Layer 7)

EBS Storage is accessed directly by Operating system or application via iSCSI or fibre channel
Accessed via API on http/https protocol

Data is divided into Fixed-size block, and each block is assigned a unique address but lack of metadata.
Data is stored in Objects, where each object includes the data identifier called metadata.

Note : We can't run an application on S3 Storage as, S3 is an Object storage device and EBS is Block storage.

We get by default 8gb of EBS volume with root disk, we can increase that volume as per need.
We will get 3IOPS perGb while creating EBS volume, Minimum IOPS after 33
Note : It is necessary to create EBS in same zone of Instance

When we use EBS storage first time we need to format the Disk, Formatting a disk mean dividing a disk of 100 GB into small units called blocks.
that is why it is called Block storage.
EFS is also a Block storage

Emphemeral storage : also called instance storage and Temporary storage.
provides temporary, block-level storage directly attached to the host computer of an EC2 instance.
It's essentially like a local hard drive for your virtual machine, offering high performance for I/O-intensive tasks. However, this storage is not persistent: data is lost when the instance is stopped, terminated, or fails.

-------------------------Virtual Private Cloud -------------------------

VPC is logical grouping of Set of IP addresses, using which we can create our own network and further divide that network in to small networks called subnets.

We create our vpc and than subnet under AWS cloud, after creation of own VPC, every instance, every storage or any network device will get the IP from the newly created VPC and subnet CIDR block.

Classful and classless addressing are methods of organizing IP addresses, but they differ significantly in their approach.
Classful addressing, the older method, divides IP addresses into fixed classes (A, B, C, D, and E), each with predefined network and host portions. This leads to inefficiencies in address allocation, especially as networks grow.
In Classfull addressing there was limited number of host and limited number of network was their.

Class A: Uses the first byte for the network ID and the remaining three bytes for the host ID. Addresses range from 1.0.0.0 to 126.255.255.255 (default subnet mask: 255.0.0.0). Total Host : 16,777,214 hosts + 2(broadcast and Gateway address)=256*256*256

Note : 127.0.0.0 reserved for loop back (127.0.0.0 - 127.255.255.254) Loopback IP address is special IP address that points to same machine.

Class B: Uses the first two bytes for the network ID and the remaining two bytes for the host ID. Addresses range from 128.0.0.0 to 191.255.255.255 (default subnet mask: 255.255.0.0). Total host :65534  + 2(broadcast and Gateway address)

Class C: Uses the first three bytes for the network ID and the last byte for the host ID. Addresses range from 192.0.0.0 to 223.255.255.255 (default subnet mask: 255.255.255.0). Total host = 254 +2 (broadcast and Gateway address)

Class D: Reserved for multicast addresses (224.0.0.0 to 239.255.255.255). : 3758096384
Class E: Reserved for future use or experimental purposes (240.0.0.0 to 255.255.255.255).

Classless addressing, also known as CIDR (Classless Inter-Domain Routing), offers more flexibility by allowing variable-length subnet masks, enabling more efficient use of IP address space and supporting larger and more diverse networks. Classless Addressing allow us to divide the network into another small network called subnet
Classless addressing allow us to break the network at any point and that we can divide into further subnets

logical addressing, use to communicate between computer to computer, ie IP Address
IPv4 is of 32 BITS, So total address will be 2^32 and IPv6 is of 128 BIT address so Total address will 2^128.
Each address is unique means each address one and only one network device. Two device can never have same address at a time

Private IP range
10.0.0.0 to 10.255.255.255/8
172.16.0.0 to 172.31.255.255/16
192.168.0.0 to 192.168.255.255/16

IP Address: A 32-bit address (for IPv4) divided into four octets (e.g., 192.168.1.0).
Subnet Mask: Determines which portion of the IP address is the network and which is the host. It can be written in dotted decimal (e.g., 255.255.255.0) or CIDR notation (e.g., /24).

The "/n" indicates the number of bits used for the network portion (e.g., /24 means 24 bits for the network, leaving 8 bits for hosts)
Number of Subnets: Depends on how many bits are "borrowed" from the host portion to create subnets.
Number of Hosts per Subnet: Depends on the remaining host bits after subnetting.

Let suppose You are given an IP range (e.g., 192.168.1.0/24). The subnet mask in CIDR notation (e.g., /24) tells you how many bits are used for the network.

For /24, 24 bits are for the network, leaving 32 - 24 = 8 bits for hosts.

If you are subnetting the network further, you "borrow" bits from the host portion to create subnets.
If you subnet a /24 network to /26, you borrow 2 bits (26 - 24 = 2) for subnetting.
Number of subnets = 2^s, where s is the number of bits borrowed for subnetting.
Borrowing 2 bits (from /24 to /26) gives 2^2 = 4 subnets.

After borrowing bits for subnets, the remaining bits are for hosts
Number of hosts per subnet = 2^h - 2, where h is the number of host bits.
For a /26 network, there are 32 - 26 = 6 host bits.
So, 2^6 = 64, So every subnet will have 64 IP address
and 64 - 2 = 62 hosts per subnet.

Subnet will be
-> 192.168.1.0 - 192.168.1.63
-> 192.168.1.64 - 192.168.1.127
-> 192.168.1.128 - 192.168.1.191
-> 192.168.1.192 - 192.168.1.255

In a Site-to-Site VPN, communication happens over the internet using public IP addresses for the tunnel endpoints. However, the traffic within the VPN tunnel is encrypted and uses the private IP addresses of the networks being connected.
