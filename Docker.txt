Docker: Docker is a open source platform or tool that allow you to pack an application and everything it needs (code, runtime, libraries, OS dependencies) 
		into a single unit called a container.
		Further we can create an image of that specific application container and create container using that image at any platform.
		
Docker Image = Read-only blueprint
			   Contains app + dependencies
			   Built using Dockerfile
			  
Docker Container: Running instance of an image

Docker Engine : create image and containers.

Dockerfile : Instructions to build image ( docker build -t myapp .)


Container: it is a new concept of virtualization, where we create VM using light weight image of OS, and we can bind the application into standardized unit.
			But container does not have its own kernel, it use the kernel of host machine OS.
			
Kernel :  A middle layer that interact with both software and hardware. like
		  App asks for memory → kernel allocates RAM
		  App reads a file → kernel talks to disk
		  App sends data → kernel handles networking
		  
		  Application   ---------> (system call) ---------> Kernel
		  
		  Hardware		---------> (driver / interrupt) -----------> Kernel

		  
		  The kernel communicates with hardware using: Device drivers, Hardware controllers(keyboard inputs, disk read write)

Note :    We can create the container of Windows OS as well, but it can run only on Windows hosts, because it uses the Windows Kernel.



Complete Flow
						Application (Software)
								↓
						System Call
								↓
							Kernel
								↓
						Device Driver
								↓
							Hardware

Containers communicate directly with the host operating system's kernel. And It Help us to use Hardware in more efficient manner.

1. Portable : share across the system without OS dependencies

2. Lightweight : it uses the OS images which is lightweight, size is very low
   as compared to actual OS
3. Container has its own environment independent of container host machine,
   it may happen container have different version of java installed and
   base machine have different version of java.

Docker : it is an executable file that has instruction to build containers using the images, where images are the read only templates.
		 Docker images and docker container has similar kind of relation that we have between class and object. 
		 
		 docker images is a blueprint to create container.
		 docker container is a running instance while docker image, and image is read only templates.

---------------------Docker File
Docker file: use to create costum image.
				A Dockerfile is a text file that contains instructions to build a Docker image.

			Image = blueprint
			Container = running instance of that image

			we can create any normal file. default name is Dockerfile but if we create file with different name than
			we need to use -f flag while building image.


In Docker file we only give the instruction that we use to install any package or application.

Basic Structure of a Dockerfile
Instructions : FROM,	 WORKDIR,	COPY,	RUN,	EXPOSE,		CMD/ENTRYPOINT


Example: Let’s say you want to run a Node.js app.
	
	myapp/
		|-->Dockerfile
		|-->package.json
		|-->app.js
			
	FROM node:20-alpine						//base image
	WORKDIR	/app							//Docker will create a directory in Base image under root i.e /app
	COPY	. .								// It will copy the entire content of current dir of docker host to Workdir
	RUN npm install							//Install Dependencies
	EXPOSE 3000								//Expose the port for application for runtime
	CMD ["node", "app.js"]					// Starting the app -> node app.js

	Command : docker build -t nodeApplication .			//Command will create image of name nodeApplication in Docker system.
	
Note : Each instruction of Dockerfile is considered as layer.


Example Dockerfile
--------------------------------------------------------------------------------
| FROM ubuntu:14.04                                                     |  // From Keyword, From which base image we are
| RUN apt-get update && apt-get install -y apache2                      |     creating image.
| RUN apt-get install -y tree openssh-server openssh-client             |
| RUN cd /var/www/html                                                  |
| RUN echo "Welcome to India" > /var/www/html                           |
| RUN service apache2 start                                             |
--------------------------------------------------------------------------------


Now We can build a new image using the above Dockerfile.
Command: docker image build -t myimage:1 .          (-t Tag,  () Dot mean file is at current path.
                                            Docker will automatically find the Dockerfile at given path, only if
                                            Name is Dockerfile, otherwise we need to give flag -f file_name
                                            and 1 is verion of image

-------------------------------Lecture 23

Docker Swarm: we can create n number of container on one docker host, but what if the main docker host machine is disrupt
or
    stopped working than??
    So using Docker Swarm We can create cluster of Docker host.

    On clustered machine we need to install docker package, and it is must required that all the clustered machine
able to
    ping each other.

    Note : By default Docker swarm is disabled, we need to enable it explicitly. Swarm has its own ingress Load Balancer

    We need to configure one node of docker host as Master node and rest as worker node.
        If we have to configure 100 containers than we need to distribute them among each node of docker host.
        if any one docker host get down or destroy than its container will get shift to rest of nodes.

    all the service are going to manage from master node like creation of container on worker node anything.
    We must have two or more than two manager or master node.
    Note : we can configure ingress load balancer, so that it can distribute the load to all the container of docker.
