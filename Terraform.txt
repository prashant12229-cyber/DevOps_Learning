Terraform: terraform is a open source, infrastructure as a code, cloud management tool, it allows us to provision cloud
resources across the multiple cloud provider. We can create infrastructure on any cloud using terraform code.

How to install and configure terraform -----------------------

go to https://terraform.io/download.html

after downloading terraform for specific OS, cd to terraform downloaded directory
now need to set the path of terraform : copy the terraform path and add path in env variable of mycomputer

now hit command terraform from any directory.

Download Visual Studio and install hashicorp terraform plugin (it will help syntax correction)

For linux : download terraform zipped package and keep it in linux OS
unzip terraform_1.1.0_linux.zip

we can add path in linux
    export path=$PATH:$(pwd) present working directory or path to terraform binaries
    or
    put the terraform binaries inside any path of $PATH Variable

like first hit : echo $PATH
    /usr/local/bin:/usr/local/bin:/local/sbin:usr/bin (this will show multiple path which are added as system
variable)
    cp -r terraform /usr/local/bin
    now we can run terraform command from anywhere in linux OS

    or
    open terraform.io and copy the link of any linux os terraform package (copy link location using right click)
    and hit -> wget https://release.hashicorp.com/terraform/0.13.5/terraform_0.13.5_linux_amd64.zip on linux machine

-------------------------------Lecture 10

Count : the count parameter is use to reduce redundancy. if we want to create one resource multiple time than, we can use
count keyword
    by passing the value of count as number of times we have to create resource.

Example

resource "aws_instance" "Ec2_instance" {
    ami="ami-678hvcuisd"
    instance_type="t2.micro"
    count=5                 // by providing count as 5, terraform will create 5 instance of t2.micro type.
    tags= {
        name="dev.${count.index}" // count.index will give the index value and append it to name dev like dev.0, dev.1,
dev.2 so on.
    }
}

Note : when we use count parameter, it will create instance of name like Ec2_Instance[0], Ec2_Instance[1], Ec2_Instance[2],
Ec2_Instance[3] etc

To provide Custom name,

resource "aws_instance" "Dev"{
    instance_type=var.instancetype["dev"]   //it will pick the instance type of t2.micro from above instancetype variable
    ami=var.image[0]
    count=var.input == "dev" ? 10 : 0
}

resource "aws_instance" "Test"{
    instance_type=var.instancetype["test"]   //it will pick the instance type of t2.nano from above instancetype variable
    ami=var.image[1]
    count=var.input == "test" ? 5 : 0
}

resource "aws_instance" "PROD"{
    instance_type=var.instancetype["prod"]   //it will pick the instance type of t2.small from above instancetype
variable
    ami=var.image[2]

}

Note : As we can see the above count parameter have condition of matching dev,test, and prod. If the input matches with any
resource
    condition, that terraform will create resource in that specific env.

If first time we provide input as dev than terraform will create 10 instance
If after input value of dev, we again run terraform apply and give input as test, that it will destroy the 10 instance of DEV
and  create 5 instance of test
If after input value of dev, we again run terraform apply and give input as prod, that it will destroy the 5 instance of DEV
and  create 2 instance of prod

-------------------------------Lecture 14  State Management

Note : Whenever the project of terraform starts, we will run the three command init, plan, apply, destroy and after running the
		apply command
		
		it will first check the resource file i.e resource.tf available in which directory and it will search for terraform.tfstate file
		in same directory.
		if terraform do not find the terraform.tfstate file that it will create the resources on aws cloud, because whenever
	
we deploy the project first time than obviously it will not find any .tfstate file

After creating the resources for the first time, terraform will gather all the information of resources and create .tfstate
file

Now, .tfstate file exist in directory

if someone again run the terraform apply command than terraform will compare the resource file and .tfstate file, and if
no change find
    than it will show terraform up to date.

but if someone add new resource and than run terraform apply, than terraform will check the changes and create the new
resources
    or it will update the old resources and update the same in .tfstate file

whenever terraform will make change in architecture, it will keep the backup of old .tfstate.backup file

Issue Arise : let there are two engineer vikas and vipin working on same project of terraform. let vikas started the project so
vikas has
    terraform.tfstate file in his local, but now vipin wants to do some update in architecture, if vipin run the
apply command without terraform.tfstate file than terraform will create infrastructure again. So he need to have
terraform.tfstate file copy
    in his local too. but again vikas need to do something on infrastructure and he do not have latest updated
file than
    he will destroy the resource created by vipin.

Solution : configure the terraform on shared directory using NFS, SAMBA, EFS etc. or create account on github
    OR
    last solution is will store the terraform.tfstate file will store on cloud like AWS S3 and enable the versioning
    we will define the tfstate file is at S3 bucket. No Tension of Push and Pull form GIT
    We Need to use DynamoDB for using the file lock feature, so that only one can work at a time on terraform.

Note : If we need to create two env. staging and prod, than we will create two different directory of terraform of name
    staging and prod. or We will use concept of workspace.

Note : We can destroy an individual resource from cloud using terraform as well using the below command
    terraform destroy -target=resource_type.resource_name
    terraform destroy -target=aws_instance.Ec2_Instance               //command
	
	
-------------------------------Lecture 15

Terraform State Management Lab

1. Create aws.tf a resource creation file inside the project directory, and there is nothing except this file in the directory
2. Run terraform init  on current directory
3. Run terraform plan  (plan command check the aws.tf file and its syntax and show what will create and what will destroy)
4. Run terraform apply  (Now this command will create resources and get the resources information and keep it in aws.tfstate file)
5. Now whenever next time terraform apply will run, terraform will compare the aws.tf and aws.tfstate file and create one more file
    aws.tfstate.backup file  and we can even validate the difference of aws.tfstate.backup and aws.tfstate file

Now we want that aws.tfstate should not store at local, it must store at remote storage. For this we need to define this in
aws.tf file only
as describe below. and run terraform apply and the aws.tfstate file will create on S3 bucket.

aws.tf
    provider "aws"{
        region =""
        access-key=""

Terraform Modules: Terraform module is basically a container for a set of Terraform configuration files that are grouped together
				to manage a piece of infrastructure as a reusable unit.
				
				It is similar as a function in any programming language where repeating the same Terraform code again and again,
				you put it into a module and call it whenever you need it.

Any terraform project that we write as a code is a module in itself, that we can use to rebuild an infrastructure on different cloud

	root module: where run out terraform init, plan, and apply command. all the module written under root is called child modules.
	
	By default, when we run terraform plan command it look for file in current directory only which is level zero, and if we have create another nested directory called named as module
	than we need to call it in terraform file at level zero.
	
	Calling of module from level zero
	
	instance.tf
		
		module "mywebserver"{
			source='./modules/webserver'			//where mywebserver is directory at level 1, which is a nested directory or module. under which we will create a different .tf file
			image_id="svdsvsbsb"
			instance_type="t2.small"			//instead of values we can pass the variable from the variable.tf file which is at level zero of root module.
			key_name="${var.key_name}"
			instance_type="${var.instance_type}"
			image_id=${var.image_id}
		}

Note : when we run terraform init command, it will initialize the variable for current directory only, so for modules, we need to define in the module block seperately.
	
	We can get the output from the module as well, module returns 
	
	we can write the output.tf file in child module and output block in root directory to get it print.
		
		output.tf file in child module
			
			output publicIP{
				value=aws_instance.web.public_ip
			}
			
			
		
		
		
		module "mywebserver"{
			source='./modules/webserver'			//where mywebserver is directory at level 1, which is a nested directory or module. under which we will create a different .tf file
			image_id="svdsvsbsb"				//passing these value to child module
			instance_type="t2.small"				//passing this value to child module
			key_name="${var.key_name}"
			instance_type="${var.instance_type}"

		output 	mypublicIP {
			
			value = module.mywebserver.publicIP			//value coming from child module
		}

Terraform Data Block

A data block in Terraform is used to read information from existing resources or services, without creating or modifying them.

resource block → creates/updates/deletes infrastructure.

data block → only fetches information about something that already exists.

Example: 

Use of Existing VPC

data "aws_vpc" "default" {
  default = true
}

resource "aws_subnet" "example" {
  vpc_id     = data.aws_vpc.default.id
  cidr_block = "10.0.1.0/24"
}

Fetching Machine Image

data "aws_ami" "amazon_linux" {
  most_recent = true

  filter {
    name   = "name"
    values = ["amzn2-ami-hvm-*-x86_64-gp2"]
  }

  owners = ["amazon"]
}

resource "aws_instance" "example" {
  ami           = data.aws_ami.amazon_linux.id
  instance_type = "t2.micro"
}
